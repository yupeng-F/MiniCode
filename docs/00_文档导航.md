## 3. 每份文档分别负责什么

### `AGENTS.md`

仓库级入口文档。

作用：
- 让新会话中的模型快速知道项目是什么
- 让协作者快速知道当前阶段和阅读顺序
- 记录不应该违背的顶层约束

### `01_项目目标与实施路线.md`

项目上位文档。

作用：
- 说明项目为什么做
- 说明服务于什么目标
- 说明阶段性实施路线

### `02_系统架构与模块设计.md`

系统总设计文档。

作用：
- 说明总体架构
- 说明协作范式
- 说明各模块边界

### `03_智能体协作_状态流转与权限设计.md`

执行规则文档。

作用：
- 定义各个 agent 的角色
- 定义状态机和返工路径
- 定义权限分层和审批矩阵

### `04_运行时与记忆系统设计.md`

底层能力设计文档。

作用：
- 定义 Harness Runtime
- 定义 Memory System
- 说明执行安全和上下文治理怎么落地

### `05_项目结构与开发计划.md`

落地实施文档。

作用：
- 定义目录结构
- 定义代码应该落在哪
- 定义接下来怎么逐步实现

### `06_核心数据结构设计.md`

接口与 schema 文档。

作用：
- 定义系统关键数据结构
- 统一 graph、agent、runtime、memory 之间的接口语言
- 作为后续代码实现的结构基础

### `07_项目完成度追踪.md`

状态跟踪文档。

作用：
- 记录各阶段完成状态
- 记录最新测试结果
- 记录技术栈与配置信息

## 4. 为什么现在只保留这几份文档

因为当前阶段最重要的是：
- 不丢设计信息
- 但也不要让文档数量本身成为负担

所以现在采用的原则是：
- 可以合并的合并
- 不方便合并的保留独立
- 后续优先更新现有文档，而不是继续拆新文档

## 5. 后续维护规则

- 每次关键沟通后，优先更新已有文档
- 只有当某块内容明显无法放进现有文档时，才新增文档
- 文档命名统一使用中文，方便快速理解
