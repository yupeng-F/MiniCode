## 三、Phase 2：Master-Specialist 架构改造 — ✅ 完成

### 3.1 核心改动

| 组件 | 文件 | 状态 | 说明 |
|------|------|------|------|
| **Master Agent** | `agents/master.py` | ✅ | LLM 驱动调度，检索长期记忆后决策 |
| **图结构重构** | `orchestrator/graph.py` | ✅ | Master→Specialist→Master 循环 |
| **Master 路由** | `orchestrator/master_router.py` | ✅ | `route_master` 机械查表，`route_after_specialist` 支持工具执行路由 |
| **ToolRegistry** | `runtime/tool_registry.py` | ✅ | 工具注册 + 按角色权限绑定 |
| **工具权限接入** | `runtime/harness.py` | ✅ | preflight() 检查 ToolRegistry 权限 |
| **Agent 工具查询** | `orchestrator/agent_node.py` | ✅ | build_agent_input 按角色注入可用工具 |
| **Specialist 清理** | `agents/*.py` | ✅ | 5 个 Specialist 均已接入 |

### 3.2 修复的关键 Bug

| Bug | 原因 | 修复 |
|-----|------|------|
| `tool_requests` 指数增长 | `apply_decision` 返回全量 state，LangGraph `merge_lists` reducer 反复拼接 | 改为返回增量（仅新元素） |
| `tool_results` 重复 | `execute_tool` 同上的问题 | 改为返回增量 |
| Master→Coder 死循环 | `route_after_specialist` 只回 Master，不执行工具 | 增加 `execute_tool` 路由分支 |
| Master 记忆检索崩溃 | `master.py` 用了未定义的 `_store` | 改为调用 `_get_memory_store()` |
| ChromaDB 模型下载阻塞 | `all-MiniLM-L6-v2` 79MB 模型下载慢 | 增加 `FastEmbeddingFunction` 轻量方案 |

### 3.3 图流程

```
START → task_intake → master_plan
  → (route_master) → explorer/coder/reviewer/tester/memory_writer
    → (route_after_specialist)
      → 有低风险待执行工具 → execute_tool → 回 Specialist
      → 有高风险待执行工具 → execute_tool_approval
        → 审批通过 → execute_tool → 回 Specialist
        → 审批驳回 → master_plan（注入驳回 ToolResult）
      → 无待执行工具 → master_plan（循环）
  → (task_complete) → finalize/force_finalize → END
```

### 5.3 修复记录

| 问题 | 根因 | 修复 |
|------|------|------|
| SSE 事件不推送 | 后台线程用 `loop.call_soon_threadsafe()` 推送到未启动的事件循环 | 改用 `threading.Queue` + 直接 `queue.put()`，SSE 用 `run_in_executor` 异步读取 |
| 前端无实时反馈 | SSE 事件从未到达前端 | 同上，事件流恢复正常 |
| 消息重复 | `updateFromState` 每次 SSE 事件都追加同一条消息 | 添加基于内容 hash 的消息去重 |
| 加载遮罩 | 全屏遮罩 + 禁用输入框让用户无法操作 | 移除遮罩，执行中可继续打字 |
| 端口冲突 | 旧进程残留占用 8080 端口 | 增加端口清理说明 |
| Shell 占位符 | `_run_shell` 返回固定文本 | 接入 subprocess 安全执行 |

## 六、Phase 4.5：Shell 沙箱 — ✅ 已完成

### 6.1 实现情况

| 组件 | 文件 | 状态 | 说明 |
|------|------|------|------|
| ShellSandbox | `runtime/shell_sandbox.py` | ✅ | subprocess 执行 + 多层安全防护 |

### 6.2 安全防护

| 防护层 | 措施 | 说明 |
|--------|------|------|
| 命令黑名单 | 正则匹配拦截 | 拦截 `rm -rf /`、`mkfs`、`dd if=`、`shutdown`、`reboot`、fork 炸弹等 |
| 超时保护 | 30 秒硬限制 | 防止死循环、卡死、fork 炸弹 |
| 输出上限 | 100KB 截断 | 防止大量输出撑爆内存 |
| 工作区限制 | 限制在项目目录 | 通过 `cwd` 参数限制执行目录 |

### 6.3 可用角色

- Coder：可执行构建、运行脚本等命令
- Tester：可运行测试套件

### 6.4 已知限制

- Shell 命令在宿主系统直接执行（非容器隔离），依赖黑名单防护
- `run_shell` 标记为 `risk_level=high`，策略引擎返回 `allow_with_approval`，但审批节点尚未接线
