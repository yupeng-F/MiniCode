## 设计哲学

| # | 哲学 | 要求 |
|---|------|------|
| 1 | 极简 = 少决策负担 | 首屏只允许 1 个主任务 + 1 个 CTA、每步 1 个决定 |
| 2 | 视觉 = 策略可视化 | 层级/留白/对比度服务转化目标、视觉重点 = 业务重点 |
| 3 | 一致性优先于炫技 | 相同语义 → 相同组件/反馈/文案模式、动效仅解释状态变化 |
| 4 | 设计可工程化 | 所有样式映射 design token、禁止不可实现的视觉方案 |

## PRD 到高保真流程

1. **需求解构**：提取主目标/主路径/关键风险，标注闭环环节与转化指标，明确 Out of Scope
2. **交互原型（低保真）**：信息架构 + 页面流，覆盖主路径 + 异常路径，定义每步状态反馈与恢复动作；修改既有页面时，须输出「现状 → 目标」对照
3. **高保真视觉**：建立视觉层级（主操作→核心信息→辅助信息），固化排版/间距/颜色/组件状态，产出可开发标注（token 映射）；每个改动页面须给出可直接对照的 HTML 原型或 PNG 设计稿
4. **设计验收**：与 PRD 一一对照 → 与前端评审实现成本 → 通过质量清单

## 界面规范

**信息层级**：一级=当前任务与状态 | 二级=结果解释与下一步 | 三级=辅助说明与可选配置

**视觉**：对比建立优先级、留白用于分组、强调内容密度与阅读节奏

**组件行为**：按钮须完整状态（default/hover/active/loading/disabled）、表单实时校验就地显示、异步操作须进度感知+回退

**动效**：进入/离开 120-240ms、重要状态切换 200-300ms 缓动、必须降低认知成本

**注意力窗口**：0-3s 标题即价值 → 3-15s 可马上开始 → 15-60s 可见进度+可恢复 → 60s+ 复用路径可见

## 交付标准

### 必须交付

1. 完整页面流（主路径 + 异常路径）
2. **变更说明**：每个页面标注「修改现有」或「新增」，新增须说明理由
3. **页面对照表**：页面 → 现状页面/截图 → 目标原型/设计稿 → 核心比对点
4. **版式整洁度清单**：对齐基线、视觉分组、主次层级、信息密度
5. **状态画面**：按 UI_DESIGN_SYSTEM.md §5 状态完备清单（9 项），不可降级或自定义
6. 组件状态板 + 标注规范（栅格/间距/字号/颜色/圆角/阴影），所有数值**必须**引用 UI_DESIGN_SYSTEM.md 的 token，禁止新增旁路风格
7. 交互动效说明（触发/时长/缓动/终态；时长缓动用 `--motion-*` token）
8. **数据示例清单**：每个页面列出原型示例的内容类型/状态/边界值（如消息类型 text/image/voice/video/file），由实现端 mock fixtures 严格覆盖（参见 `lint/ui-contracts.mjs::createMockMatrix`）
9. **Token 使用清单**：列出该页面用到的 tokens；如需新增，先提交「规范更新」任务扩展 `tokens.css` + UI_DESIGN_SYSTEM.md，禁止在设计稿内私设 token

> ⚠️ **迭代增强原则**：修改现有页面数量应 ≥ 新增页面数量，否则须说明理由。

### 质量自检

- PRD 语义 100% 对齐、状态完备、核心路径 ≤ 3 步每步 1 决策
- 每个改动页面均有设计文档路径 + 原型/设计稿路径，可直接进行设计/实现对照
- 版式整洁度清单已覆盖对齐、分组、主次、密度，文案具体可执行
- 埋点齐全、Mobile+Desktop 断点明确、token 可工程落地
- 4 条哲学有对应设计决策、注意力窗口标注、Microcopy 标准

## BOSS 设计走查（L3 门控）

> ⛔ 设计完成后必须 BOSS 走查。**未通过禁止进入技术方案和代码阶段**。AI 到达此节点须停止执行，输出走查摘要并等待 Boss 确认。

**交付物**：HTML 原型或 PNG 设计稿 + 走查引导（主路径步骤+设计决策说明+影响范围说明）

**走查维度**：① 增强 vs 新建判断 ② 产品主张体现 ③ 信息架构 ④ 视觉层级 ⑤ 交互流畅度

**通过标准**：无 ❌ 不可接受项，⚠️ 高优项须修改后重新走查。

## AI 执行协议

**允许工具**：文件读写/搜索、explore 子代理、`frontend-design`（HTML 原型）、`canvas-design`（PNG 设计稿） | **禁止**：bash 执行、代码修改

> **知行合一**：设计不止于文档，须产出可交互的原型验证设计意图。

**执行步骤**：
1. 需求解构（从 PRD 提取目标/路径/风险）
2. 信息架构（页面流 + 注意力窗口标注）
3. 交互原型（主路径+异常，每步 1 决策，覆盖所有状态）
4. 视觉层级（信息分层，视觉重点=业务重点）
5. 组件状态板 + 标注输出（token 映射）
6. 质量自检
7. 原型产出（HTML 原型保存至 `docs/design-docs/prototypes/`）

**原型标准**：HTML 可浏览器直接打开（内联 CSS/JS）、PNG 至少覆盖主路径关键页面
