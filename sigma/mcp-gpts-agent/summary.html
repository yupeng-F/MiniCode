📝 MCP 与 GPTs 学习笔记

2026-05-21 · 约 45 分钟 · 中级 · 5 个概念完成

一、一句话核心

MCP = 标准 | GPTs = 产品
MCP 定义"怎么连" · GPTs 解决"怎么用"
二者不在同一层面，可以互补

二、核心概念

🤖 AI Agent = 大脑 + 手脚
Agent = LLM（大脑） + 工具（手脚） + 记忆 + 状态管理 + 权限控制
LLM 本身只是"大脑"，接了工具才能行动。但 N 个工具 × N 种协议 = 适配噩梦。
🔌 MCP · Model Context Protocol
开放协议，由 Anthropic 提出。作用是统一 Agent 与工具之间的通信规范，相当于 AI 界的 USB-C 接口。

架构：
Host（LLM 应用） → Client（会话管理） ↔ Server（工具服务）

传输方式：
stdio（本地进程间管道）或 SSE（远程 HTTP）

三大核心能力：
🛠️ Tools — LLM 调用的动作（有副作用）
📖 Resources — LLM 读取的数据（只读）
💡 Prompts — 预制提示词模板

通信格式：
基于 JSON-RPC 2.0，工具参数描述使用 JSON Schema

核心优势： - 一套标准对接所有工具 - 换任何 LLM 都无缝兼容 - 本地/远程部署均可
🧩 GPTs · OpenAI 的产品化 Agent
OpenAI 在 ChatGPT 内部提供的功能，让普通用户无需编程即可创建自己的定制 AI 助手。

主要构成：
- Instructions：自定义指令
- Knowledge：上传知识文档
- Actions：配置外部 API（本质上也是工具调用）

局限性：
✗ 只能用 OpenAI 模型
✗ 只能在 ChatGPT 界面内使用
✗ 定制深度有限，无工作流编排
✗ 数据在 OpenAI 服务器上

类比：像 Dify 这样的低代码平台也能构建 AI 应用，但更开放——支持多模型、可独立部署、MCP 协议。

三、完整对比

🔮 MCP

  • 本质：通信协议
  • 提出者：Anthropic
  • 开放性：开放标准
  • 支持模型：任意
  • 用户：开发者
  • 可编程性：协议层，完全灵活
  • 部署：本地 / 远程
  • 定位：基础设施（协议层）
  • 类比：USB-C 标准

🧩 GPTs

  • 本质：应用产品
  • 提出者：OpenAI
  • 开放性：闭源，仅限 OpenAI
  • 支持模型：仅 OpenAI
  • 用户：普通用户 ~ 开发者
  • 可编程性：配置化，有限定制
  • 部署：仅 OpenAI 云端
  • 定位：应用产品（应用层）
  • 类比：品牌手机（封闭生态）

四、Agent 生态全景

MCP — 工具连接标准，Anthropic 提出，开放协议
GPTs — OpenAI 产品化 Agent，ChatGPT 内部定制助手
Skills / 插件 — 平台特定的行为扩展（如 Claude Code Skills）
Agent 框架 — 构建 Agent 的开发框架（LangChain / AutoGen / CrewAI）
低代码平台 — 可视化构建 AI 工作流（Dify / Coze / Flowise）
托管服务 — Agent 即服务（Anthropic Agent / OpenAI Agent SDK）

用户 → GPTs (产品) → GPT-4o (模型) → MCP (标准) → 工具 (API/数据库/文件)

五、金句总结

MCP 是 Agent 的 "USB-C 接口"——定义了工具怎么插、数据怎么流。
GPTs 是 OpenAI 做的 "品牌手机"——开箱即用但只能在它的生态里转。

二者不矛盾——MCP 是开放标准，理论上 GPTs 也可以基于它构建。
标准越统一，产品越强大。
