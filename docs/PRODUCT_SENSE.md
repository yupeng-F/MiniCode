# Product Sense

> 面向资深产品经理的产品 Taste 与决策规范。专用于 `product` 任务类型。
> 业务目标、用户画像与 Roadmap 见 [USER_STORIES.md](../USER_STORIES.md)。

**产出物**：PRD 保存至 `docs/product-specs/[feature-slug].md`（须更新 `index.md`，关联 User Story ID）

**文档约束**：单份 PRD 不超过 **500 行**。超出须拆分为多个独立 PRD。

**渐进式加载**：生成 PRD 前先读 `docs/product-specs/index.md` 和关联 User Story，只打开与当前需求强相关的历史 PRD。历史 PRD 仅作参考，新 PRD 必须写清对旧方案的变更、优化、删除；不得直接改旧 PRD 来表达新需求。

---

## 核心价值原则

我们卖的是**确定性**：决策确定性（知道下一步做什么）+ 执行确定性（秒级完成，无等待焦虑）。

每个需求必须回答：**它是否增强了用户的确定性？**

### JTBD 验证

每个功能须用 JTBD 框架验证。PRD 须含对照表（场景/用户工作/旧方案痛点/我们的优势），内容从关联 User Story 提取。

---

## 价值闭环

每个模块须定义从"触发意图"到"价值确认"的完整链路，每环节可观测可度量。

**断裂点分析**：PRD 须对每个可能中断的环节定义：① 监控指标 ② 自动降级策略 ③ 恢复动作引导

---

## 产品一贯主张（不可摇摆）

| # | 主张 | 核心约束 |
|---|------|---------|
| 1 | 速度是功能 | P99 < 8s、LCP < 2s（3G）、交互反馈 < 100ms、优先乐观更新 |
| 2 | 零摩擦 | 能自动推断不让输入、能自然语言不加表单、主路径 ≤ 3 步每步 ≤ 1 决策 |
| 3 | 默认值即产品观点 | 默认值服务转化目标、不可中庸、须体现策略 |
| 4 | 可行动数据优先 | 输出"下一步建议"非纯数字、描述"行为强度+时间窗口+推荐动作" |
| 5 | 状态即体验 | 空态教育、加载态掌控感、错误态可执行解法 |

---

## 用户注意力曲线（S0-S4）

| 阶段 | 时间窗口 | 设计要求 |
|------|---------|---------|
| S0 | 0-3s | 标题即价值，首屏 1 个主动作 |
| S1 | 3-15s | 示例输入 + 预期结果可见 |
| S2 | 15-60s | 进度反馈 + 可撤回 |
| S3 | 1-3min | 阶段化反馈，禁止白屏 |
| S4 | 3min+ | 归因证明 + 一键复用 |

**入门曲线**：30s 理解价值 → 3min 完成首次任务 → 5min 看到 Aha Moment → 30min 学会复用

---

## 交互与展示标准

**反馈**：点击 < 100ms 回执、AI 生成全程可见、错误内联+解决动作、破坏性操作二次确认+撤销窗口

**展示**：首屏 1 个主目标 + 1 个 CTA、次要信息延后、结果页含"下一步动作"

**Microcopy**：具体 > 通用、行动 > 状态、解释 > 报告。禁止"操作成功""发生错误""请输入内容""加载中..."

## PRD 转译规范

### 四步法

1. 需求抽象：用"三次为什么"还原动机
2. 闭环定位：标注作用于价值闭环的哪一环
3. 最小化设计：定义最小可验证版本 + Out of Scope
4. 可测化落地：状态、埋点、指标、验收阈值

### PRD 最小模板（不可删）

```
1. 背景与目标
2. 关联 User Story ID
3. 影响范围（必填）
   3a. 修改现有页面  3b. 修改现有组件  3c. 修改现有 API  3d. 新增项（须说明理由）
4. 用户流程（主路径 + 异常路径 Mermaid）
5. 功能规格（字段、状态、文案、空态、错误态）
6. 数据埋点
7. 验收标准（P50/P95/P99、转化率、成功率）
8. 非功能要求 + Out of Scope
```

> ⚠️ **迭代增强原则**：3d（新增）条目数 > 3a+3b+3c（修改）时须说明理由。

### PRD 自检（通过才可进入设计）

**第零级**：影响范围已填、新增项有理由、修改路径在代码库中存在
**第一级**：开发无需补问、QA 可编写用例、状态全覆盖、指标可量化
**第二级**：JTBD/价值闭环/断裂点/5 条主张/S0-S4/Microcopy/入门曲线 全部体现

---

## 优先级与取舍

- P0：影响价值闭环成立 | P1：直接提升转化留存 | P2：提升质感
- **直接拒绝**：单一用户诉求无复用价值、教育成本高、与闭环无关、复杂度高无 ROI

---

## AI 执行协议

**允许工具**：文件读写/搜索、explore 子代理 | **禁止**：bash 执行、代码修改

**执行步骤**：
1. 需求抽象（三次为什么 + JTBD）
2. 闭环定位（映射到价值闭环）
3. 主路径设计（标注 S0-S4，≤ 3 步）
4. 异常路径（断裂点 + 降级 + 恢复）
5. 功能规格（追溯产品主张）
6. 埋点定义
7. 验收标准
8. 两级自检
