## 2. 代码目录说明

### `src/multi_agents/agents/`
- Master Agent + 5 个 Specialist Agent 的实现
- `master.py` 核心调度逻辑（LLM 驱动决策 + 记忆检索）

### `src/multi_agents/orchestrator/`
- LangGraph 主图、路由和状态流转逻辑
- `graph.py` 构建 Master→Specialist→Master 循环
- `master_router.py` 动态路由 + 硬上限保护（HARD_CEILING=5）
- `agent_node.py` 节点包装器 + 增量 state 返回（避免 merge_lists 重复）

### `src/multi_agents/runtime/`
- Harness Runtime、Policy、Approval、Workspace、Tool Registry、Shell Sandbox
- `tool_registry.py` 按角色控制工具可见性
- `harness.py` preflight() 做 Runtime 层权限拦截
- `shell_sandbox.py` subprocess 安全执行（黑名单 + 超时 + 输出上限）

### `src/multi_agents/memory/`
- ChromaDB 长期记忆（4 个 Collection）
- FastEmbeddingFunction（轻量，免模型下载）
- SummaryManager（LLM 摘要 + 滑动窗口）
- ContextManager（记忆检索注入）

### `src/multi_agents/tools/`
- 原子工具定义（file_tools / shell_tools / search_tools）
- ToolSpec 描述 + allowed_roles 权限绑定

### `src/multi_agents/llm/`
- LLM 客户端封装（OpenAI 兼容，百炼 DashScope）
- 6 个角色 system prompt（master / planner / explorer / coder / reviewer / tester）
- `agent_helper.py` 统一调用入口 + 错误降级

### `src/multi_agents/interfaces/`
- CLI 入口（支持 4 种 mode）
- Web UI（FastAPI + 静态前端 + 工作空间选择 + 历史持久化）

### `src/multi_agents/observability/`
- Trace / Audit 骨架

### `src/multi_agents/schemas/`
- 核心数据结构（state / agent / tool / memory / policy）

## 3. 核心流程说明

### Master-Specialist 循环

```
START → task_intake → master_plan
  → (route_master) → explorer/coder/reviewer/tester/memory_writer
    → (有工具待执行) → execute_tool → 回 Specialist
    → (无工具待执行) → master_plan（继续循环）
  → (task_complete=true) → finalize/force_finalize → END
```

关键设计：
- Master Agent 的 LLM 输出 `next_agent` 枚举值，路由只做机械跳表
- Specialist 是 stateless 的，每次调用获得干净的上下文
- ToolRegistry 在 Runtime 层拦截非法工具调用
- 3/5 软硬返工上限（LLM 3 次软上限，路由 5 次硬截断）

### 记忆系统

- **长期记忆**：ChromaDB 4 个 Collection，按记忆类型分离
- **短期记忆**：滑动窗口裁剪（tool_results 保留错误，plan 截断，task_memory 截断）
- **上下文压缩**：每 3 轮对 context_bundle 做 LLM 摘要压缩
